# Spec-per-Stage（SpS）· 以阶段为规范

> **Spec-per-Stage: Refactoring the Interaction Interface of AI Programming — An Attention-Economics Perspective**
> 面向 AI 编程的交互界面重构 —— 一个注意力经济学视角

📄 成品：[以阶段为规范-AI编程交互界面重构论文.pdf](以阶段为规范-AI编程交互界面重构论文.pdf)

---

## 问题

AI 编程正在成为软件生产的主导方式，但现有讨论大多聚焦于**"模型能生成什么"**，而较少审视**"人如何向模型下达指令"**。

自由提示词的三种失效模式：

- **结构性重复** —— 每个会话都在重新发明语法；
- **注意力稀释** —— 不变量（项目结构这类每次都该相同的决策）挤占了变量（真正携带信息的细节）；
- **错误晚发现** —— 缺陷跨阶段放大。

## 方案

**以阶段为规范（SpS）**：以一套通用规范充当 AI 编程的**"SQL 语法"**，

- 将一次开发任务表达为若干条**规范语句**；
- 每条语句由不变的**模板骨架 τ** 与开发者填写的**变量细节 δ** 构成；
- 语句在提交生成前经过一道**轻量校验**（如同 SQL 的语法与类型检查）；
- 每个阶段（产品方案设计 → 技术方案设计 → 产品实现）的出口设置**人工评审门禁**（如同事务提交）。

## 三重论证

| 论证 | 要点 |
|---|---|
| 注意力是真正稀缺的资源 | 模型上下文注意力随无关标记注入而稀释，人的评审注意力受带宽约束，自由提示词把两者的注意力消耗在"每次重新决定项目结构"这类**不变量**上 |
| 不变量吸收 | 通用规范把结构性决策从每次会话的**随机变量**变为**确定性常量**，注意力因此重新集中于真正携带信息的变量细节——正如数据独立性曾把查询者从访问路径中解放出来 |
| 门禁有界 | 阶段门禁使缺陷在引入后的**最近边界**被捕获，修复动作退化为"重新生成一条语句"，错误传播与修改半径被结构性压低 |

## 与 F2F 的衔接

SpS 组织 AI 编程的**输入端（指令）**，与姊妹篇 Feature-per-File（F2F）——组织**输出端（文件）**——互补衔接：**实现语句以 F2F 特征文件为输出单元**，复杂任务通过语句分解为多个独立文件的增量拼装。

## 其他内容

- 规范语句的**参考语法**（reference grammar）；
- **规范控制台**的交互语义：语句、校验、提交、回滚与历史；
- 以**"活动趋势查询"**为运行示例的完整工作流；
- **生命周期分工模型**：结构生成期（0→1）使用 SpS 快速构建结构完整、功能可用的全新项目；局部微调期（1→1.1）依据**相位迁移判据**回落到传统 AI 编程工具，规范产物作为两相之间的交接资产。
